# Phase 7 Generalization and Rollout Validation 실행 프롬프트

## 0 작업 목적

기존 Phase 1부터 Phase 6까지의 연구에서는 `oftplus_h5_vision`, checkpoint step 28560을 대상으로 5개 episode와 225개 Real Sim paired frame을 분석하였다.

기존 결과는 다음 가능성을 보여주었다.

* 전체 Representation Gap의 크기와 Action Gap의 크기는 동일한 정보를 제공하지 않을 수 있다.
* 전체 hidden difference보다 policy-sensitive component가 action prediction에 더 큰 영향을 줄 수 있다.
* Progress 또는 phase-conditioned hidden correction이 offline Action Gap을 줄일 수 있다.
* P4 letterbox preprocessing이 기존 데이터에서 Action Gap을 크게 줄였다.
* 밝기와 contrast 등 observation-level 통계 정렬은 Action Gap 개선을 보장하지 않았다.
* Camera-like perturbation과 preprocessing 효과는 additive하지 않고 condition-dependent할 수 있다.

그러나 기존 결과는 동일 작업 및 제한된 환경에서 수집한 5개 episode에 한정되어 있으며, 실제 closed-loop rollout 성능과 연결되지 않았다. 또한 Action Gap이 L2 metric과 gripper dimension에 과도하게 의존했을 가능성이 있다.

Phase 7의 장기 목적은 다음 질문에 답하는 것이다.

```text
다양한 객체 위치, 조도, 카메라 및 환경 조건에서도
Policy-Relevant Representation Gap이 유지되는가?

전체 Sim Real feature distribution을 정렬하는 방법보다
policy-sensitive component를 정렬하는 방법이
action prediction과 실제 rollout 성능을 더 효율적으로 개선하는가?

이 결론은 L1, L2, Huber, rotation error,
gripper disagreement와 timing error 등
평가 metric을 바꾸어도 유지되는가?
```

# 4 기존 데이터의 다중 Metric 재평가

기존 L2 metric을 삭제하지 말고 baseline으로 유지하세요.

## 4.1 Metric 수학적 정의

모든 metric에 대해 다음을 명시하세요.

* 입력 action dimension
* normalization 여부
* dimension aggregation
* chunk aggregation
* frame aggregation
* episode aggregation
* epsilon과 outlier 처리
* 단위

특히 다음을 혼용하지 마세요.

```text
L2 norm = sqrt(sum(error_dimension²))

RMSE = sqrt(mean(error_dimension²))
```

Action dimension이 고정되어 있더라도 두 값의 scale과 정의를 별도로 기록하세요.

## 4.2 전체 Action Metric

각 frame과 action chunk에 대해 다음을 계산하세요.

* L1 norm
* MAE
* L2 norm
* RMSE
* Huber distance
* Cosine distance
* Chunk mean
* Chunk median
* Chunk max
* Per-dimension absolute error
* Per-dimension squared error

Huber delta 후보:

```text
0.01
0.05
0.1
```

Action scale을 확인한 뒤 값이 부적절하면 config로 조정할 수 있지만, 변경 이유와 최종 값을 기록하세요.

Cosine distance에서는 zero 또는 near-zero vector 문제를 처리하세요.

```text
epsilon을 명시
near-zero vector 수 보고
제외 또는 대체 규칙 기록
```

## 4.3 Translation Metric

Translation dimension이 확인된 경우 다음을 계산하세요.

* Translation L1 norm
* Translation MAE
* Translation L2 norm
* Translation RMSE
* Translation cosine distance
* X, Y, Z별 MAE
* Chunk timestep별 translation error
* Episode별 translation error

실제 단위 decode가 검증된 경우에만 다음을 추가하세요.

* cm error
* mm error

Normalized metric과 physical-unit metric을 분리해 저장하세요.

## 4.4 Rotation Metric

Rotation 표현을 먼저 검증하세요.

Euler 또는 rotation vector인 경우:

* Dimension별 MAE
* L2 norm
* RMSE
* Degree와 radian 단위 구분

Quaternion 또는 rotation matrix로 신뢰성 있게 변환할 수 있는 경우:

* Geodesic angular error
* Degree error
* Radian error

Euler angle에는 wrapping을 적용하세요.

```text
wrapped_error = atan2(sin(delta), cos(delta))
```

단순 L2와 geodesic angular error가 다른 결론을 보이는지 분석하세요.

## 4.5 Gripper Metric

Gripper decode 코드를 확인하고 실제 threshold를 사용하세요.

Threshold가 확인되지 않아 임시 threshold를 사용해야 한다면 다음처럼 표시하세요.

```text
ASSUMED_THRESHOLD
```

그리고 threshold sensitivity를 분석하세요.

가능한 metric:

* Continuous gripper absolute error
* Continuous gripper squared error
* Binary open close disagreement rate
* Accuracy
* Precision
* Recall
* F1 score
* False-open rate
* False-close rate
* Gripper close timing error
* Gripper open timing error
* Phase별 disagreement
* Episode별 disagreement
* Chunk 내부 transition 위치 차이

GT gripper state가 없으면 accuracy, precision, recall과 F1을 계산하지 말고 Real Sim disagreement만 보고하세요.

## 4.6 Sequence Metric

Episode의 진행 속도와 frame correspondence 차이를 고려해 다음을 계산하세요.

* Raw timestamp-aligned trajectory error
* Progress-normalized trajectory error
* Dynamic Time Warping distance
* Gripper event-aligned error

DTW가 시간 불일치를 숨길 수 있으므로 raw timestamp 결과를 반드시 함께 제시하세요.

## 4.7 Metric별 방법 순위

다음 기존 방법을 가능한 범위에서 비교하세요.

```text

Global mean correction
Progress correction
Phase correction
Progress plus phase correction
Random matched-norm control
Shuffled progress control
Wrong-direction control
P1 direct resize
P2 square crop
P3 center crop

```

Metric에 따라 방법 순위가 달라지는지 분석하세요.

순위 일치도:

* Spearman rank correlation
* Kendall rank correlation

Method 수가 부족하거나 tie가 많으면 해석의 한계를 기록하세요.

## 6.2 분석 질문

다음 질문에 직접 답하세요.

1. Alignment 단계에서 Gripper Gap이 큰 이유는 무엇인가?
2. 현재 action과 미래 action chunk 중 어디에서 차이가 발생하는가?
3. Real prediction이 더 일찍 close하는가?
4. Sim prediction이 더 일찍 close하는가?
5. 두 출력이 다르지만 둘 다 planner 또는 GT와 맞지 않는 경우가 있는가?
6. Grasp-close 단계보다 alignment 또는 hold 단계에서 gap이 큰 이유는 무엇인가?
7. Letterbox가 gripper timing을 실제로 개선했는가?

# 7 Global Sim Real Distribution Alignment Baseline

이 절은 장기 Phase 7 계획에 포함하되, 이번 Priority 1에서는 기존 feature만으로 안전하게 실행할 수 있는 방법만 수행하세요. GPU full-forward가 필요하면 `GPU_REQUIRED`로 표시하고 Priority 2로 넘기세요.

## 7.1 비교 방법

가능한 범위에서 다음 방법을 비교하세요.

* Global mean shift
* Mean variance alignment
* CORAL
* MMD-based alignment
* Wasserstein 또는 Sinkhorn alignment
* PCA delta subspace correction
* Progress-conditioned correction
* Phase-conditioned correction
* Policy-sensitive low-rank correction

## 7.2 평가 유형 구분

모든 alignment 결과를 다음 세 유형 중 하나로 분류하세요.

### Inductive evaluation

```text
Train episode 또는 train environment에서만 alignment fitting
Held-out Real input에 고정된 변환 적용
Held-out Sim feature나 test distribution으로 parameter를 재추정하지 않음
```

조건을 충족하고 현재 Real input만으로 적용 가능하면 다음 상태를 부여할 수 있습니다.

```text
DEPLOYABLE_CANDIDATE
```

### Transductive evaluation

```text
Held-out 또는 test distribution 전체를 alignment fitting에 사용
개별 paired correspondence는 사용하지 않을 수 있으나
test distribution 정보가 필요함
```

다음 상태로 표시하세요.

```text
ANALYSIS_ONLY_TRANSDUCTIVE
NOT_DEPLOYABLE_AS_EVALUATED
```

### Paired oracle evaluation

```text
Test frame의 paired Sim hidden 또는 paired Sim delta를 사용
```

다음 상태로 표시하세요.

```text
ANALYSIS_ONLY_ORACLE
NOT_DEPLOYABLE
```

## 7.3 중요 제한

* 모든 deployable candidate는 train episode에서만 fitting하세요.
* Held-out episode나 condition의 Real 또는 Sim feature를 이용해 parameter를 재추정하지 마세요.
* Hyperparameter도 train data에서 선택하세요.
* Feature Gap 감소와 Action Gap 감소가 같은 방향인지 별도로 분석하세요.
* 저장된 hidden을 수정해 action head만 다시 실행한 결과와 전체 VLM full-forward 결과를 구분하세요.
