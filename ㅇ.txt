# 2. 기존 데이터에 대한 다중 Metric 재평가

현재 Action Gap은 L2 중심으로 평가되었습니다. L2는 삭제하지 말고 baseline metric으로 유지하면서 다음 metric을 추가하세요.

## 2.1 전체 Action Metric

각 frame 및 action chunk에 대해 다음을 계산하세요.

* L1 / MAE
* L2 / RMSE
* Huber distance
* Cosine distance
* Chunk mean
* Chunk max
* Chunk median
* Per-dimension absolute error
* Per-dimension squared error

Huber의 delta는 최소 3개 후보를 비교하세요.

```text
delta = 0.01, 0.05, 0.1
```

Action scale을 확인한 뒤 값이 부적절하면 config로 조정하고 근거를 기록하세요.

## 2.2 Translation Metric

* Translation L1
* Translation L2
* Translation cosine distance
* X/Y/Z dimension별 MAE
* 실제 단위로 decode 가능하면 cm 또는 mm 단위 오차

Normalized action이라면 normalized metric과 decoded physical metric을 분리하세요.

## 2.3 Rotation Metric

Rotation 표현을 먼저 확인하세요.

* Euler 또는 rotation vector라면 dimension별 MAE와 L2
* Quaternion 또는 rotation matrix로 변환 가능하면 geodesic angular error
* Degree 및 radian 단위를 명시

단순 L2와 실제 회전각 metric이 다른 결론을 보이는지 분석하세요.

## 2.4 Gripper Metric

현재 전체 Action Gap이 Gripper에 지배되는지 다시 검증하세요.

가능하면 다음을 계산하세요.

* Continuous gripper absolute error
* Binary open/close disagreement rate
* Accuracy
* Precision
* Recall
* F1-score
* False-open rate
* False-close rate
* Gripper close timing error
* Gripper open timing error
* Phase별 gripper disagreement
* Episode별 gripper disagreement
* Chunk 내부 gripper transition 위치 차이

Gripper threshold가 명시되지 않았다면 모델 decode 코드를 확인하고 실제 threshold를 사용하세요. 임의의 0.5 threshold를 사용해야 한다면 가정임을 명시하고 threshold sensitivity를 평가하세요.

## 2.5 Sequence Metric

Episode 진행 속도와 frame correspondence 차이를 고려해 다음을 추가하세요.

* Dynamic Time Warping distance
* Gripper event-aligned error
* Progress-normalized trajectory error

단, DTW가 실제 시간 불일치를 숨길 수 있으므로 raw timestamp 기준 결과도 함께 제시하세요.

## 2.6 출력

```text
01_multimetric_reanalysis/
├─ frame_metrics.csv
├─ episode_metrics.csv
├─ phase_metrics.csv
├─ action_dimension_metrics.csv
├─ gripper_event_metrics.csv
├─ metric_robustness_summary.csv
├─ metric_rank_consistency.csv
├─ summary.json
└─ report.md
```

각 correction 및 preprocessing 방법의 순위가 L1, L2, Huber, Gripper metric에서도 동일하게 유지되는지 비교하세요.

방법 간 순위 일치도는 Spearman 또는 Kendall correlation으로 정리하세요.

* Sim gripper action

# 5. Global Sim-to-Real Distribution Alignment Baseline

현재 핵심 가설은 전체 representation gap을 줄이는 것보다 policy-relevant component를 줄이는 것이 중요하다는 것입니다.

이 가설을 검증하기 위해 Global Alignment를 명시적인 baseline으로 구성하세요.

가능한 범위에서 다음 방법을 구현·비교하세요.

* Global mean shift
* Mean/variance alignment
* CORAL
* MMD-based alignment
* Wasserstein 또는 Sinkhorn alignment
* PCA delta subspace correction
* 기존 Progress-conditioned correction
* 기존 Phase-conditioned correction
* 기존 Policy-sensitive low-rank correction

비교 metric:

* Observation Gap
* Vision Gap
* Projector Gap
* Action Hidden Gap
* Sensitive Energy
* Null Energy
* Translation Error
* Rotation Error
* Gripper Error
* Action L1/L2/Huber
* GT Action Error가 있으면 GT 기준 결과

중요:

* Global Alignment는 train episode만으로 fitting하세요.
* Held-out episode 또는 held-out condition에서는 fitting하지 마세요.
* Test frame의 paired Sim hidden을 사용하는 방법은 `ANALYSIS_ONLY_NOT_DEPLOYABLE`로 표시하세요.
* 현재 frame의 Real input만으로 적용할 수 있는 방법은 `DEPLOYABLE_CANDIDATE`로 표시하세요.
* Feature Gap 감소와 Action Gap 감소가 항상 같은 방향인지 분석하세요.

# 7. Camera Shift 재실험 설계

기존 C2는 1280px 이미지에서 24px 이동시켰지만, P4+C2 결합에서는 224px 이미지에서 24px를 이동시켜 상대 이동량이 달라졌습니다.

이를 보완하세요.

## 원본 1280px 조건

```text
-32, -24, -16, -8, -4, 0, +4, +8, +16, +24, +32 px
```

## Letterbox 224px 조건

원본 이동 비율과 대응되도록 다음을 우선 사용하세요.

```text
-8, -6, -4, -2, 0, +2, +4, +6, +8 px
```

# 9. Rollout 평가 프로토콜 보완

현재 패키지는 Offline Gap 분석은 충분하지만 실제 Rollout 평가가 없습니다.

실제 로봇을 이 작업에서 임의로 제어하지 마세요. 먼저 실행 가능한 안전 protocol과 코드 interface를 작성하세요.

## 9.1 Stage A: Offline

다음을 비교합니다.

* Baseline policy
* Global Alignment
* P4 또는 최적 입력 전처리
* Progress/Phase correction
* Policy-relevant correction
* 입력 전처리 + correction

평가:

* Sim–Real Action Gap
* GT Action Error
* Gripper timing
* Failure phase

## 9.2 Stage B: Shadow Mode

실제 카메라와 robot state를 사용해 VLA inference를 수행하지만 policy action은 로봇에 전달하지 않습니다.

실제 제어는 기존 motion planner 또는 검증된 controller가 수행합니다.

기록 항목:

```text
image
raw_state
planner_action
policy_action
raw_policy_action
decoded_action
executed_action
inference_start
inference_end
timeout
communication_status
```

## 9.3 Stage C: Closed-loop Rollout

Shadow Mode 검증 후에만 수행합니다.

필수 안전 기능:

* Inference timeout 시 HOLD
* 통신 단절 시 HOLD
* Workspace limit
* Joint limit
* Velocity limit
* Acceleration limit
* Collision stop
* Emergency stop
* Gripper command saturation
* Action smoothing
* 5Hz control 확인
* OFT input 1Hz, action chunk K=5 처리 확인
* 현재 chunk 실행 중 새 inference 수신 시 정책 정의

## 9.4 Rollout 조건

최소 비교 조건:

```text
R0: Baseline
R1: Global Alignment
R2: Best Input Preprocessing
R3: Progress/Phase Correction
R4: Policy-Relevant Alignment
R5: Input Alignment + Policy-Relevant Correction
```

# 13. 실행 우선순위

모든 실험을 한 번에 실행하기 어렵다면 다음 순서로 진행하세요.

## Priority 1: 기존 데이터만으로 즉시 실행

* Audit
* L1/L2/Huber 재평가
* Translation/Rotation/Gripper 분리
* Gripper timing 분석
* Episode-level 통계
* 기존 방법의 Metric별 순위 비교

## Priority 2: 추가 GPU 실행

* Camera Shift Sweep
* Letterbox Ablation
* Global Alignment full-forward
* Held-out condition 평가

## Priority 3: 새로운 데이터 필요

* 객체 위치 변화
* 조도 변화
* 실제 카메라 변화
* Leave-one-condition-out

## Priority 4: 실제 로봇 승인 필요

* Shadow Mode
* Closed-loop Rollout
* Task Success 평가

각 Priority가 끝날 때마다 중간 보고서를 작성하고, 다음 단계에 필요한 데이터·GPU·실물 로봇 조건을 명시하세요.

마지막으로, 실행한 코드의 syntax check와 입력 파일 validation을 수행하고, 재현 가능한 실행 명령을 `README.md`에 정리해 주세요.
