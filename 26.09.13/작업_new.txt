# A0509 VLA Sim-to-Real 최종 실험 진행 프롬프트

## 0. 연구 목적

A0509 로봇에서 Sim-trained VLA의 Sim-to-Real deployment를 분석한다.

이번 연구의 목적은 단순히 Simulation과 Reality의 이미지를 비슷하게 만드는 것이 아니다.

핵심 연구 질문은 다음과 같다.

> **Simulation과 Reality 사이의 visual observation gap이 VLA 내부 representation과 action prediction에 어떻게 전달되며, 이러한 gap이 실제 로봇의 task performance와 어떤 관계를 가지는가?**

전체 연구 흐름은 다음과 같이 정의한다.

**Environment / Control Alignment**

↓

**Observation Gap**

↓

**Representation Gap**

↓

**Action Gap**

↓

**Real-world Performance**

최종적으로는

> **어떤 Sim-to-Real gap이 실제 VLA deployment에 중요한지, 그리고 어느 수준의 environment alignment가 필요한지**

분석하는 것을 목표로 한다.

# 4. Phase 1 — Initial Condition / Coordinate Alignment

기존 Real dataset을 기준으로 Sim과 Real의 초기 조건을 맞춘다.

확인 대상:

* initial joint
* gripper
* robot home
* cube position range
* instruction
* camera preprocessing

현재 Real200 first row 기반 HOME 정합 결과를 우선 사용한다.

---

# 5. Phase 2 — Tool / Camera Coordinate Alignment

현재 가장 중요한 미해결 문제다.

trajectory replay 자체는 정상적으로 수행되고 있으나 Real과 Sim camera view가 크게 다르다.

따라서 먼저 coordinate-frame 차이를 해결한다.

다음을 구분한다.

* Base
* Flange
* Tool0
* TCP
* Camera parent
* Dataset EEF frame

Real dataset의 `end_effector_pose`가 어떤 frame을 의미하는지 확인한다.

Sim의 tool0/TCP와 직접 비교 가능한지도 검증한다.

각 환경의 transform chain을 다음 형태로 정리한다.

`Base → Flange → Tool/TCP → Camera`

기존 분석에서 Real raw tool orientation과 Sim tool orientation 사이에 거의 일정한 큰 frame offset이 관찰되었으므로 이를 우선 검증한다.

무작정 camera rotation/translation sweep을 추가하지 않는다.

---

# 6. Phase 3 — Camera Intrinsic / Extrinsic Alignment

## Intrinsic

Sim과 Real에 대해 다음을 비교한다.

* resolution
* fx/fy
* cx/cy
* horizontal FoV
* vertical FoV
* aspect ratio
* distortion
* crop
* resize
* model preprocessing

Raw image와 model-input image를 구분한다.

---

## Extrinsic

Real trajectory에서 cube 또는 known target의 image coordinate를 이용해 camera extrinsic을 추정한다.

각 timestep의 Real pixel:

`p_real(t) = [u_real, v_real]`

Sim projection:

`p_sim(t; T_camera)`

를 비교하여

`Σ ||p_real(t) - p_sim(t)||²`

를 최소화하는 camera transform을 찾는다.

가능하면 grasp 전 안정적인 구간을 우선 사용한다.

기존에 계산한 frame-corrected camera transform과 extrinsic estimation script를 먼저 검증한다.

---

# 7. Camera Alignment 완료 기준

다음 조건을 만족한 후 본격적인 observation-gap 분석으로 넘어간다.

* cube가 Real/Sim에서 유사한 image region에 위치
* cube pixel trajectory 방향이 유사
* 접근 과정에서 object scale 변화가 유사
* gripper/body occlusion이 크게 다르지 않음
* FoV가 유사
* crop/resize 이후 model input layout이 유사

Pixel-identical할 필요는 없다.

목적은 camera geometry mismatch라는 큰 confounding factor를 제거하는 것이다.

---

# 8. Phase 4 — Control / Temporal Alignment

이 단계에서는 **새로운 Real robot 동작을 우선 요구하지 않는다.**

먼저 기존

`raw_dataset_oft_200`

을 분석한다.

확인 항목:

* timestep interval
* effective control frequency
* EEF translation per timestep
* EEF rotation per timestep
* gripper transition
* trajectory duration

그리고 동일 Real trajectory를 Sim에서 replay하여 비교한다.

즉:

`Real Dataset Δpose`

vs

`Sim Replay Δpose`

를 비교한다.

현재 기준:

* Real ≈ 5 Hz
* Sim replay ≈ 5 Hz
* OFT K=5
* OFT input ≈ 1 Hz / control 5 Hz

를 검증한다.

단순히 "Real이 3배 느리므로 Sim을 3배 느리게 한다"는 식으로 결정하지 않는다.

---

## 추가 Real Calibration이 필요한 경우

기존 dataset으로 확인할 수 없는 다음 항목이 연구에 반드시 필요할 경우에만 짧은 Real calibration 동작을 수행한다.

* command-to-motion latency
* servo response
* 동일 command에 대한 실제 displacement
* settling time

즉 Phase 4까지는 가능한 한 기존 dataset을 활용한다.

# 11. Phase 7 — Layout Design

단순 random rollout만 사용하지 않는다.

기존 Simulation cube placement 범위를 확인하고 Real에서도 동일 범위를 사용한다.

가능하면 3×3 grid를 사용한다.

예:

X:

* Left
* Center
* Right

Y:

* Near
* Middle
* Far

총 9 layout.

권장:

`9 layouts × 3 repetitions = 27`

필요하면 center/extreme condition을 추가하여 약 30회로 구성한다.

Sim과 Real의 target-position distribution을 최대한 동일하게 한다.

# 14. Phase 10 — Representation Gap

동일 paired Sim/Real observation을 VLA에 넣는다.

현재 가능한 주요 layer:

* `vision_backbone.input`
* `vision_backbone.output`
* `projector.output`
* `action_hidden_states.input`
* `action_head.output`

목적은:

> **Sim/Real visual gap이 VLA 내부에서 어느 정도 유지되고 action 쪽으로 전달되는지**

확인하는 것이다.

Sim과 Real의 latent가 반드시 같아야 한다고 가정하지 않는다.

---

# 15. Representation Metrics

최소 다음을 사용한다.

### Paired cosine distance

`1 - cosine(z_sim, z_real)`

### Normalized L2

`||z_sim-z_real|| / sqrt(d)`

### Distribution metric

가능하면 MMD.

필요하면 충분한 sample에서 Fréchet-style feature distance를 검토한다.

서로 다른 layer는 dimension과 scale이 다르므로 raw L2 magnitude를 직접 비교하지 않는다.

---

# 16. Representation Visualization

PCA 또는 UMAP 등을 사용할 수 있다.

단 visualization은 qualitative evidence로 사용한다.

Quantitative evidence는:

* cosine
* normalized L2
* MMD

등을 사용한다.

# 21. Shadow Mode의 목적

Shadow Mode의 핵심은:

> **동일한 reference trajectory를 실제 로봇이 다시 수행할 때 현재 Real observation에 대해 VLA가 어떤 action을 예측하는지 확인하는 것**

이다.

Simulation에서도 동일 dataset trajectory를 replay했으므로 다음 비교가 가능하다.

`Sim Replay Observation → VLA → a_sim`

`Real Replay Observation → VLA → a_real`

`Dataset Reference Action → a_GT`

따라서 Shadow에서는:

1. Sim vs Real observation gap
2. Sim vs Real representation gap
3. `a_sim vs a_real`
4. `a_sim vs a_GT`
5. `a_real vs a_GT`

를 비교한다.

---

# 22. Shadow Mode Safety

Dataset trajectory replay이므로 AI 제어보다 위험은 낮지만 safety system은 유지한다.

* communication disconnect → hold
* replay timeout → hold
* trajectory tracking abnormality → hold
* emergency stop 가능
* episode reset/relaunch

모든 safety event를 기록한다.

# 30. Phase 15 — Gap vs Real Performance

최종 분석 단계다.

각 layout/episode에 대해 다음을 연결한다.

* observation gap
* vision feature gap
* projector/hidden gap
* action gap
* real success/failure

최종적으로 다음 관계를 분석한다.

`Observation Gap → Representation Gap`

`Representation Gap → Action Gap`

`Action Gap → Real Success`

필요하면 Spearman correlation을 사용한다.

예:

`ρ(Image Gap, Performance)`

`ρ(Vision Gap, Performance)`

`ρ(Action Gap, Performance)`

Success가 binary라면 단순 상관계수만 사용하지 말고 성공/실패 group 비교 또는 logistic regression도 검토한다.

# 35. 결과 해석 시 주의사항

다음과 같이 단정하지 않는다.

* Sim/Real latent는 같아야 한다.
* feature gap이 크면 VLA가 반드시 실패한다.
* brightness 차이가 failure의 원인이다.
* image similarity가 높으면 Real success도 높다.
* action gap이 하나의 원인만으로 발생한다.

대신 단계별 실험을 통해 관계를 확인한다.

특히 최종적으로 중요한 것은 단순히:

`Sim image ≈ Real image`

가 아니다.

더 중요한 것은:

`Same/Comparable Physical State`

↓

`Sim/Real Observation`

↓

`VLA Representation`

↓

`Appropriate Action`

이다.

따라서 raw pixel gap이 남아 있더라도 VLA representation/action이 안정적이고 Real task가 성공한다면 그 차이는 deployment에 덜 중요한 gap일 수 있다.

반대로 작은 visual 차이가 representation/action을 크게 변화시키고 Real failure와 연결된다면 중요한 Sim-to-Real factor로 볼 수 있다.

# 최종 원칙

이번 연구에서 Real robot 사용 시점을 명확하게 구분한다.

**Offline 단계**

기존 Real dataset + Simulation 사용.
가능한 한 Real robot을 새로 움직이지 않는다.

**Shadow 단계**

기존 dataset trajectory를 Real robot에 replay한다.
VLA는 inference만 수행한다.
VLA output은 robot control에 사용하지 않는다.

**Prototype / Full Real 단계**

VLA output을 실제 Real robot control에 사용한다.

따라서 실험 전체의 핵심 연결은:

**Existing Real Dataset ↔ Simulation**

↓

**Offline Sim-to-Real Gap**

↓

**Dataset-Trajectory Real Shadow**

↓

**VLA Closed-loop Real Verification**

↓

**Gap ↔ Real Performance**

이다.

현재 가장 먼저 해결해야 할 것은 추가 Real rollout이 아니라 **Real/Sim camera/tool-frame alignment를 완료하고 신뢰할 수 있는 paired Sim-Real observation을 구축하는 것**이다.
