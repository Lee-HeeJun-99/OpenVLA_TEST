# A0509 VLA Sim-to-Real 연구 최종 실험 계획 및 진행 지시

현재 A0509 로봇의 VLA Sim-to-Real 실험을 진행 중이다.

이번 연구의 핵심 목적은 단순히 Sim과 Real 이미지를 비슷하게 만드는 것이 아니다.

**시뮬레이션과 실제 환경 사이의 visual observation distribution gap을 측정하고, 그 차이가 VLA 내부 visual representation과 action distribution에 어떻게 전달되는지 분석한 뒤, 실제 로봇 성공률과의 관계를 확인하는 것**이 최종 목표다.

전체 연구 흐름은 다음을 기준으로 한다.

**Environment Alignment
→ Observation Gap
→ Representation Gap
→ Action Gap
→ Real-world Performance**

모든 작업은 이 인과관계가 깨지지 않도록 진행한다.

# 2. 현재 가장 중요한 미해결 문제

현재 핵심 blocker는 **camera geometry / coordinate-frame alignment**다.

trajectory replay 자체는 정상적으로 동작하지만 Real과 Sim의 camera view가 크게 다르다.

기존에 다음 실험을 이미 수행했다.

* X rotation sweep
* RY/RZ rotation sweep
* Y translation sweep
* X/Y translation sweep
* left/right camera 비교
* camera optical axis 기록
* Real raw tool frame과 Sim tool frame orientation 차이 분석

단순 camera local rotation/translation sweep만으로 Real view가 재현되지 않았다.

또 Real raw tool orientation과 Sim tool orientation 사이에 거의 일정한 큰 frame offset이 존재할 가능성이 확인됐다.

따라서 추가 blind sweep을 무작정 진행하지 않는다.

---

# 3. Phase 1 — Coordinate / Camera Alignment

가장 먼저 해결해야 한다.

## 3.1 Tool-frame convention 확인

Real dataset의

`end_effector_pose`

와 Sim에서 사용하는

`tool0 / TCP / planner frame`

의 정의를 확인한다.

다음을 명확히 구분한다.

* robot flange
* tool0
* TCP
* camera parent frame
* dataset EE frame

Real과 Sim quaternion을 단순 비교해서는 안 된다.

각 frame 간 transform chain을 명확히 정리한다.

가능하다면 다음 구조로 정리한다.

`Base → Flange → Tool0/TCP → Camera`

Real과 Sim 각각의 transform을 표로 작성한다.

---

## 3.2 Camera intrinsic 비교

Sim과 Real에 대해 다음을 확인한다.

* image resolution
* fx
* fy
* cx
* cy
* horizontal FoV
* vertical FoV
* aspect ratio
* crop
* resize
* distortion
* model preprocessing

특히 실제 ZED 영상이 model input으로 들어가기까지의 전체 preprocessing chain을 확인한다.

Sim camera image에도 동일한 preprocessing을 적용한다.

---

## 3.3 Camera extrinsic 추정

추가적인 manual angle sweep보다 다음 방식을 우선한다.

Real trajectory에서 cube 또는 known target의 image coordinate를 얻는다.

각 timestep에서

`(u_real, v_real)`

을 확보한다.

Sim에서는 corresponding robot/cube state를 사용하여 camera transform 후보에 따른 projected pixel

`(u_sim, v_sim)`

을 계산한다.

다음 loss를 최소화하는 extrinsic을 찾는다.

`sum_t || p_real(t) - p_sim(t) ||²`

가능하면 trajectory 전체보다 우선 object가 아직 grasp되지 않은 안정적인 구간을 사용한다.

camera extrinsic optimization 결과는 무조건 육안 contact sheet와 함께 검증한다.

단순 pixel loss가 작다는 이유만으로 camera calibration 성공으로 판단하지 않는다.

---

# 4. Camera alignment 완료 조건

다음 조건을 만족해야 이후 image/feature 본실험으로 넘어간다.

Real과 Sim paired trajectory에서:

* cube가 유사한 screen region에 위치
* cube pixel trajectory 방향이 유사
* camera가 object에 접근하면서 object scale 변화가 유사
* gripper/body occlusion pattern이 크게 다르지 않음
* FoV 차이가 허용 가능한 수준
* crop/resize 적용 후 model input layout이 유사

완전히 pixel-identical할 필요는 없다.

목적은 **physical state가 같은데 camera geometry가 달라 발생하는 불필요한 confound를 제거하는 것**이다.

# 5. Phase 2 — Control / Temporal Alignment

Camera와 별개로 control condition도 정리한다.

현재 OFT 조건:

* control 5 Hz
* image/model input 1 Hz
* action chunk K=5

이를 실제 runtime과 Sim에서 동일하게 재현한다.

단순히 “Real이 약 3배 느리므로 속도를 3배 변경”하는 방식만 사용하지 않는다.

다음을 측정한다.

* command frequency
* observed TCP translation per action
* observed TCP rotation per action
* command-to-motion latency
* action duration
* servo update frequency
* settling time

동일 action command에 대해 Sim과 Real의 실제 state delta를 비교한다.

필요한 경우 다음 형태로 결과를 만든다.

`command → Real Δpose`

`command → Sim Δpose`

control mismatch와 visual mismatch를 분리한다.

Real robot 실험에서는 반드시 다음을 구현하거나 기존 구현을 확인한다.

## inference timeout

timeout 발생 시:

`hold`

즉시:

`hold`

2. robot safe hold
3. 필요 시 home 복귀
4. model/runtime state reset
5. 다음 episode 재시작

긴급정지 이벤트도 dataset/log에 기록한다.

# 9. Layout 설계

무작위 30회만 수행하지 않는다.

Sim에서 기존에 사용하는 cube placement 범위를 먼저 확인한다.

Real에서도 동일한 physical placement range를 사용한다.

가능하면 placement 범위를 grid로 분리한다.

예:

* X: Left / Center / Right
* Y: Near / Middle / Far

즉 3×3 = 9 layout.

권장 구성:

`9 layouts × 3 repetitions = 27`

필요하면 center/edge/extreme case를 추가하여 약 30 rollout으로 맞춘다.

Sim과 Real의 layout distribution이 최대한 같도록 한다.

# 10. Phase 5 — Observation Gap

paired dataset을 기준으로 image distribution을 분석한다.

단순 전체 dataset histogram뿐 아니라 paired timestep 분석을 함께 수행한다.

## Raw image statistics

* RGB mean/std
* HSV mean/std
* brightness/luminance
* contrast
* RGB histogram
* luminance histogram
* saturation

## Geometry-sensitive metrics

camera 정합이 충분한 paired image에 대해:

* SSIM
* PSNR
* LPIPS

SSIM/PSNR은 geometry alignment가 안 된 상태에서는 주요 metric으로 사용하지 않는다.

LPIPS 역시 pixel geometry mismatch 영향을 받으므로 해석에 주의한다.

# 11. Target color confound

Real200은 orange target을 사용한다.

현재 확보된 Sim/training evidence만으로 학습 dataset 전체가 red-only였다고 단정하지 않는다.

두 종류의 분석을 구분한다.

## Color-controlled analysis

가능하면:

`Sim orange vs Real orange`

를 사용한다.

목적:

camera / lighting / renderer / background 차이 분석.

## Deployment-gap analysis

실제 학습/validation distribution과 Real deployment condition 차이를 그대로 포함한다.

이 경우 target color mismatch도 Sim-to-Real gap의 일부다.

두 결과를 섞지 않는다.

기존 warm-color mask 분석은 sanity check로 유지하되 cube segmentation으로 과도하게 해석하지 않는다.

# 13. Phase 7 — Representation Gap

Observation alignment 결과를 확인한 후 VLA internal feature 분석을 수행한다.

현재 기존 코드에서 가능한 layer:

* `vision_backbone.input`
* `vision_backbone.output`
* `projector.output`
* `action_hidden_states.input`
* `action_head.output`

가능하면 기존 extraction pipeline을 확장해서 사용한다.

최종 latent 하나만 보고 결론내리지 않는다.

목적은

**visual domain gap이 network를 통과하면서 어느 단계에서 유지되고 어느 단계에서 감소하는지**

확인하는 것이다.

---

# 14. Representation metrics

최소 다음을 계산한다.

## Paired cosine distance

`1 - cosine(z_sim, z_real)`

## Normalized L2

raw L2만 layer 간 비교하지 않는다.

feature dimension/scale이 다르므로

`||z_sim-z_real|| / sqrt(d)`

또는 적절한 normalization을 사용한다.

## Distribution metric

가능하면 MMD를 추가한다.

sample size가 충분할 경우 Fréchet-style feature distance도 검토할 수 있다.

layer dimension이 다르다는 이유로 서로 다른 layer의 raw L2 magnitude를 직접 비교하지 않는다.

---

# 15. Representation visualization

PCA 또는 UMAP을 사용할 수 있다.

단:

* visualization은 qualitative evidence
* MMD / cosine / normalized L2가 quantitative evidence

로 사용한다.

t-SNE/UMAP cluster separation만 가지고 domain gap이 크다고 결론내리지 않는다.

# 17. Phase 8 — Shadow Mode

Real robot은 AI가 제어하지 않는다.

모션 플래너로 실제 trajectory를 실행한다.

실제 camera image와 state를 동시에 AI 모델에 입력한다.

AI 출력은 logging만 하고 robot command로 사용하지 않는다.

비교 대상:

`Planner/reference action`

`OpenVLA Vanilla prediction`

`OFT prediction`

이번 연구 목적은 모델 간 순위 경쟁이 아니므로 Vanilla vs OFT 자체를 main question으로 만들지 않는다.

두 모델은 서로 다른 VLA 구조/학습 방식에서 Sim-to-Real gap이 어떻게 나타나는지 확인하는 secondary analysis로 사용한다.

# 24. Phase 11 — Gap vs Real Performance

이번 연구에서 매우 중요한 분석이다.

각 layout 또는 episode에 대해 다음 값을 만든다.

* image gap
* vision feature gap
* projector gap
* action gap
* success/failure

그리고 gap과 real performance의 관계를 분석한다.

예:

`Spearman(image_gap, success)`

`Spearman(vision_gap, success)`

`Spearman(action_gap, success)`

sample size가 충분하면 logistic regression 등의 단순한 분석도 검토할 수 있다.

목적은:

**어떤 종류의 Sim-to-Real gap이 실제 VLA failure를 가장 잘 설명하는가?**

를 확인하는 것이다.

# 25. 연구 질문

분석 및 실험은 다음 Research Question에 대응하도록 구성한다.

## RQ1

Sim과 Real 사이에는 어떤 visual observation gap이 존재하는가?

## RQ2

environment alignment를 적용하면 observation gap은 얼마나 감소하는가?

## RQ3

observation gap은 VLA internal representation까지 얼마나 전달되는가?

## RQ4

representation gap은 action distribution 차이와 연결되는가?

## RQ5

observation / representation / action gap 중 실제 Real success와 가장 강하게 연관되는 것은 무엇인가?

## RQ6

어떤 alignment가 실제 Sim-trained VLA의 Real deployment에 가장 중요한가?

# 26. 연구에서 과도하게 주장하면 안 되는 것

다음과 같은 표현은 피한다.

* Sim/Real latent는 반드시 같아야 한다.
* 동일 physical state이면 모든 layer feature가 같아야 한다.
* latent distance가 크면 무조건 실패한다.
* brightness 차이가 Sim-to-Real failure의 원인이다.
* feature gap이 존재하므로 encoder가 실패했다.

대신:

* domain gap이 representation에 어느 정도 전달되는지 측정한다.
* representation 차이와 action/performance 간 관계를 분석한다.
* 특정 alignment가 gap 감소와 performance 개선에 기여하는지 실험적으로 확인한다.

라고 표현한다.

# 최종 연구 방향

이번 연구는 단순한 Sim/Real image similarity 연구가 아니다.

최종적으로 다음 흐름을 검증해야 한다.

**Simulation–Reality Difference**

↓

**Observation Distribution Gap**

↓

**VLA Representation Gap**

↓

**Action Distribution Gap**

↓

**Real Robot Performance**

가장 중요한 질문은:

**“Simulation과 Reality의 어떤 차이를 어느 수준까지 정합해야 Sim에서 개발한 VLA를 Real robot에 안정적으로 적용할 수 있는가?”**

이다.

현재 단계에서는 latent/feature 분석을 더 확대하기보다 **camera/tool-frame alignment 및 paired Sim-Real observation 구축을 가장 우선적으로 수행한다.**

작업을 시작할 때 기존 기록과 코드 상태를 먼저 확인한 후, 현재 미완료된 가장 앞 단계부터 진행하고, 이미 완료된 작업은 반복하지 않는다.
