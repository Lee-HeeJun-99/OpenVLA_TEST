# 2026-09-14 Real-Sim 조건 정렬 가정 정리

## 실험 아이디어

이번 실험의 핵심 아이디어는 Real과 Sim 이미지를 같은 VLA/OFT 이미지 인코더에 넣었을 때 생성되는 token 또는 latent feature distribution을 비교하고, 그 distribution shift만으로 sim-to-real 보정 가능성을 확인하는 것이다.

즉, Real 데이터를 계속 추가 수집해서 모델을 직접 다시 맞추기보다, Sim observation이 Real observation과 latent space에서 어떻게 이동하는지 보고 그 이동을 보정할 수 있는지 확인하려는 목적이다.

## 기본 가정

가정은 다음과 같다.

- 이미지의 미세한 photoreal 차이는 latent space에 어느 정도 흡수된다.
- 조명, 재질, 그림자, 카메라의 아주 작은 extrinsic 오차까지 완전히 맞출 필요는 없다.
- 대신 모델 입력에서 큰 의미를 갖는 조건은 맞아야 한다.
- 큰 조건이 맞아야 token distribution 차이가 "task/camera/domain 차이"로 해석 가능하다.
- 큰 조건이 안 맞으면 distribution 차이가 단순한 구도 mismatch, 위치 mismatch, trajectory mismatch 때문에 생길 수 있다.

따라서 이번 단계에서는 Real과 Sim을 완벽하게 동일하게 만드는 것이 목적이 아니라, 같은 task를 같은 시야와 같은 동작 흐름에서 본다는 수준을 먼저 맞춘다.

## 맞추려는 큰 조건

### 1. 로봇 초기 HOME

Real과 Sim은 같은 HOME 계열의 joint position에서 시작하도록 맞춘다.

현재 기준:

- Real 초기 joint는 `align.py`의 HOME을 기준으로 하되 joint_6에 `+180 deg` 보정을 적용한다.
- Sim 초기 joint는 main bundle의 `a0509_home_pose.json` 기준 HOME을 사용한다.
- joint_6 값이 Real과 Sim에서 반대로 보이는 것은 정상이다.

Real 첫 step 기준:

```text
joint deg = [-182.552734, -1.072198, -41.006622, 1.256319, -113.499979, 1.499855]
```

Sim HOME 기준:

```text
joint deg = [-182.535617, -1.058471, -40.983990, 1.253979, -113.505675, -178.50025]
```

여기서 중요한 것은 absolute EEF pose 수치가 완전히 같은지가 아니라, 같은 HOME joint 계열에서 시작해 카메라 이미지상 gripper/table/cube 배치가 큰 틀에서 맞는지이다.

### 2. EEF/TCP pose 해석

Real 초기 TCP와 Sim 초기 EEF pose는 수치상 크게 다르게 보인다.

Real 초기 TCP:

```text
position m = [0.305096, -0.011829, 0.723672]
rotvec rad = [3.140020, -2.715074, 0.058476]
quat wxyz = [-0.028405, 0.211579, 0.005419, 0.976933]
```

Sim 초기 EEF:

```text
position m = [0.308365, -0.011481, 1.539019]
quat wxyz = [0.154825, -0.670850, 0.710673, -0.144685]
```

이 값은 그대로 1:1 비교하지 않는다.

이유:

- Real TCP pose는 Doosan robot/base frame 기준일 가능성이 크다.
- Sim EEF pose는 Isaac Sim world frame 기준으로 출력된다.
- 따라서 Z 값이 약 `815 mm` 차이 나는 것은 실제 로봇 자세가 그만큼 다른 것이라기보다 좌표계 원점과 frame 정의 차이로 본다.
- XY는 오히려 매우 가깝다.

```text
Real initial XY = [0.305096, -0.011829]
Sim initial XY  = [0.308365, -0.011481]
XY 차이 = x 약 3.3 mm, y 약 0.35 mm
```

따라서 이 실험에서는 EEF absolute world pose보다 이미지상 상대 구도와 HOME-relative trajectory 재현을 우선한다.

### 3. 카메라 조건

카메라는 Real과 Sim 모두 eye-in-hand 형태의 left camera를 기준으로 맞춘다.

Real:

```text
topic = /zed/zed_node/rgb/color/rect/image
camera = ZED rectified left RGB image
resolution = 1280 x 720
```

Sim:

```text
camera prim = /World/a0509/link_6/tool0/left_Camera
resolution = 1280 x 720
focalLength = 2.12
horizontalAperture = 5.376
verticalAperture = 3.024
HFoV ~= 103.47 deg
VFoV ~= 70.99 deg
```

Sim left camera mount:

```text
translate = [-0.060222793661, -0.10842505344, 0.064837748142]
rotateXYZ = [155.0000187483, 0, 0]
```

Real은 rectified image이고 Sim은 distortion 없는 perspective camera이다. 완전한 distortion matching은 하지 않는다. 이번 목적에서는 같은 left camera, 같은 해상도, 비슷한 FoV, 비슷한 화면 구도가 더 중요하다.

### 4. Task 조건

Task는 orange cube pick으로 고정한다.

```text
instruction = Pick up the orange cube.
target_color = orange
task = cube_pick
```

Sim target cube는 내부 prim 이름이 legacy로 `Cube_7cm` 또는 `red`로 남아 있지만, 실제 역할과 표시 색은 orange target이다.

Sim cube 배치 최신 기준:

```text
orange = [0.519720, 0.036990, 0.860529] m
yellow = [0.500000, -0.179512, 0.860529] m
blue   = [0.620000, 0.000488, 0.860529] m
```

orange cube 위치 결정 방식:

```text
real grasp XY = [0.539720, 0.031990] m
sim-only offset = [-0.020, +0.005, 0.0] m
sim orange XY = [0.519720, 0.036990] m
```

이 보정은 EEF/TCP absolute pose 차이 때문에 자동으로 생긴 것이 아니다. Real에서 실제로 잡는 grasp XY를 Sim에 반영한 뒤, 이미지상 gripper-cube 오차를 보고 Sim orange cube만 수동으로 보정한 것이다.

### 5. Trajectory / 제어 조건

Sim replay는 Real episode trajectory를 HOME-relative joint delta로 재현한다.

현재 source:

```text
/home/ubuntu/robot_ws/src/doosan-robot2/raw_dataset_oft/episodes/episode_000001/steps.jsonl
```

Replay 방식:

```text
home_relative = true
snap_before_capture = true
replay_rate_hz = 5.0
physics_hz = 60.0
render_hz = 30.0
```

즉 Real trajectory의 absolute EEF pose를 그대로 Sim world pose로 옮기는 것이 아니라, Real HOME에서의 joint 변화량을 Sim HOME에 적용한다.

이 방식이 현재 목적에 맞는 이유:

- Real과 Sim의 world/base frame 차이를 피할 수 있다.
- 같은 joint motion pattern을 재생할 수 있다.
- 이미지상 gripper 접근, close, lift 흐름을 비교할 수 있다.
- latent token distribution 분석에서 trajectory mismatch를 줄일 수 있다.

Real 데이터 수집:

```text
record_frequency_hz = 5.0
effective_record_frequency_hz ~= 5.0
```

Sim replay:

```text
replay_rate_hz = 5.0
```

따라서 Real과 Sim 모두 5Hz 관측 시퀀스를 기준으로 비교한다.

### 6. Gripper 조건

Dataset convention:

```text
gripper_closedness = 0.0 -> open
gripper_closedness = 1.0 -> closed
```

Real 초기 상태:

```text
gripper = 1
gripper_closedness = 0.0
state = open
```

Sim 초기 상태:

```text
actual_gripper_closedness ~= 0.009
state ~= open
```

Sim replay에서는 close 시점에서 cube attach를 사용한다.

```text
attach_cube_on_close = true
attach_distance_m = 0.30
latest attach replay index = 97
```

이는 물리 grasp 성공성을 검증하기 위한 설정이라기보다, Real과 같은 "집고 들어올리는 이미지 시퀀스"를 만들기 위한 observation 정렬 장치이다.

## 미세하게 맞추지 않는 항목

이번 실험에서는 다음 항목을 완벽히 맞추지 않는다.

- 테이블 재질의 완전한 photoreal matching
- Real ZED distortion model과 Sim perspective camera의 완전 일치
- 조명 세기, 색온도, 그림자 softness의 완전 일치
- EEF world pose의 직접적인 수치 일치
- gripper contact physics의 완전한 물리 재현

대신 다음 항목이 크게 맞는지를 확인한다.

- 같은 HOME joint 계열에서 시작하는가
- 같은 left eye-in-hand 시야인가
- 해상도와 FoV가 큰 틀에서 맞는가
- 첫 프레임에서 table, gripper, cube 구도가 유사한가
- orange target 위치가 grasp 가능한 곳에 있는가
- 같은 5Hz trajectory 흐름으로 접근, close, lift가 발생하는가
- 같은 instruction과 target color를 쓰는가
- 같은 이미지 인코더/전처리로 token을 뽑는가

## 현재까지의 판단

현재 상태는 latent/token distribution shift 실험을 위한 1차 조건으로 충분하다.

특히 다음 조건은 맞춰져 있다.

- Real/Sim HOME joint 계열 정렬
- joint_6 표현 차이는 정상 처리
- eye-in-hand left camera 사용
- 1280x720 이미지 사용
- orange cube pick task 고정
- Real trajectory를 Sim에서 HOME-relative joint delta로 재생
- Real/Sim 모두 5Hz 기준
- Sim orange cube 위치를 Real grasp XY 기반으로 배치
- 이미지상 grasp/lift가 보이도록 Sim attach 처리

따라서 다음 단계는 세부 scene tuning보다, Real/Sim 이미지 각각을 동일한 image encoder에 통과시켜 token 또는 latent feature distribution을 비교하는 것이다.

## 분석 시 주의할 점

Real TCP pose와 Sim EEF world pose를 그대로 비교하면 안 된다.

비교가 필요하면 다음 중 하나로 해야 한다.

- Sim EEF를 robot base frame 기준으로 변환한 뒤 Real TCP와 비교
- 또는 absolute pose 비교를 버리고 이미지상 상대 구도만 비교

이번 token distribution 실험에서는 두 번째 접근이 더 적합하다.

핵심은 "Sim이 Real과 완전히 같은 공간 수치를 갖는가"가 아니라, "정책의 이미지 인코더가 보는 큰 시각 조건과 task 진행 구조가 같은가"이다.
