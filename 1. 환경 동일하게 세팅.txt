1. 환경 동일하게 세팅
- 로봇 제어 속도 매칭 (지금 대비 속도 3배 정도 됨)
- 환경 얼마나 차이나는지 분석, FoV, 왜곡, Crop 등 
- 초기 환경(그리퍼 값, 관절 위치) 매핑
- OFT 같은 경우 그리퍼 Actuation 후처리 코드 필요
- 5Hz 제어 확인 (OFT 같은 경우는 제어는 5Hz로 하되, Input은 1Hz - Action Chuncking의 K값이 5로 구성되어 있음)

2. 데이터 로깅
- inference timeout, 통신 끊김 발생 시 즉시 hold 코드 구현
- image frame, raw state, AI action, raw action 모두 기록

3. Shadow Mode 
- 모션 플래닝 데이터를 기반으로 실제 카메라 영상을 두 모델에 넣음 --> 제어는 X, 실제 모션 플래닝 제어 데이터와 AI 모델들의 출력 값 비교 (입력의 분포, 모션 플래너 출력의 분포, 각 AI 모델 출력의 분포 비교) & (시뮬레이션 환경에서의 입력의 분포, 모션 플래너 출력의 분포도 체크)
- 그 다음에는 AI 모델에서 Vision Encoder가 있을 건데, Vision Encoder에 동일한 Layout에서의 실제 환경 Input, 가상 환경 input 데이터를 넣었을 때 얼마나 분포가 다른지도 분석해야 함)
> 이번 논문에서 가장 중요한건 분포임 (분포가 얼마나 범위를 벗어나는지, 얼마나 다른지를 알아야 Sim2Real, 즉 시뮬레이션 환경에서 개발한 AI 모델을 바로 Real에 붙일 수 있는 단서를 찾을 수 있음)
- rollout 30회
- instruction은 학습할때와 동일한 instruction으로 넣을 것 (pick up the {color} cube)
- 이 실험부터 큐브 위치를 정해진 범위 안에 넣어야 하는데, 이건 시뮬레이션 환경에 내가 구성해놓은게 있으니 그 범위를 참고해서 Real에 배치할 것

4. Real verification mode (프로토타입 테스트)
시작 위치를 큐브 근처
시작 위치를 큐브 ~ 시작 포즈 중앙 근처
시작 위치를 시작 포즈 근처
(각각 Rollout 5회씩)

5. Real verification mode (프로토타입 테스트 결과가 좋지 않아도 진행)
- 모션 플래닝 데이터를 기반으로 하는게 아니라 현실 실시간 데이터를 기반으로 AI 모델 제어 수행
- Rollout 30회씩 (Rollout 할때 동일한 환경 layout -> OpenVLA Vanilla 실행 -> 동일한 layout에서 OFT 실행 -> 다음 Layout으로 업데이트)
- 제어할때 모니터링할 것 (그리고 문제 발생을 대비하여 긴급 정지 코드를 설계하고, 긴급 정지 코드 후 다시 윈위치 및 AI 모델 재실행 코드를 넣을 것)
- 성공률을 Table 형태로 정리할 것, 그리고 완료되면 이 결과들을 기반으로 Codex에 해서 어떻게 학습 데이터를 재구성해야 할지, 학습을 다시해야할지를, 현실 환경을 시뮬레이터에 맞춰서 구성할지(예: 카메라 왜곡 보정, 제어 속도 매칭)를 분석할 것 
-> 현실 환경 매핑은 굳이 5번에서 안해도 되고, 3번, 4번에서 진행해도 무방
