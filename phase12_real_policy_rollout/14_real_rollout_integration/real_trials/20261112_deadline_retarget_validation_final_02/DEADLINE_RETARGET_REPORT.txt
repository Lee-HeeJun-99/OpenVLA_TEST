ServoL 실행 준비 소프트웨어 수정 — 2026-11-12

결론
기록된 발행 시점 전체 재생은 PASS. 실제 rollout release는 BLOCKED.
실제 로봇/그리퍼/정지 명령 0회. 실제 ROS transport 생성 없음.

해결한 소프트웨어 문제
1. 움직이는 도중 새 목표의 초기 속도를 0으로 재설정하지 않는다.
   기존 위치 경로/회전 arc 안에서 C2 감속하고 최신 목표로 전환한다.
2. 오래된 목표를 누적 실행하지 않는 latest-only 대기 큐를 사용한다.
3. 활성화 시 원래 source timestamp로 남은 유효시간을 계산한다.
   기존 최대 tick gap 0.1초 두 구간을 endpoint/다음 목표 전환 여유로
   확보하고, 남은 시간에 맞는 quintic 실행 진행률을 산정한다.
4. 속도/가속도 한계를 지킬 수 있는 부분까지만 진행한다. 모델 raw action,
   limited action, 원래 목표/예산은 수정하지 않는다. 실제 실행 부분은
   planned_execution_fraction/fresh_horizon_s 로그에 별도로 기록한다.
5. source timestamp 갱신, 유효시간 연장, 속도/가속도 검사 제거 없음.

중요한 의미 변화
이는 원본 delta 전량 실행을 보장하지 않는다. freshness와 기존 동적 제한을
함께 지키기 위한 실행 구간 제한이다. 재생의 223 활성 구간 중 220개에서
deadline에 맞춘 계획 진행률이 1보다 작았다. 해당 계획 진행률 중앙값은
0.37027, 최소값은 0.06813이다. 이후 새 목표가 도착해 안전 감속하면
실제 완료 비율은 이 초기 계획 진행률과도 다를 수 있다.
이를 full-delta 실행 또는 실제 task 성능 개선으로 주장하지 않는다.

이 값들은 라이브러리 설치 문제가 아니며, 오류 메시지를 지우기 위해

현재 코드 그대로 실제 rollout이 시작되지는 않는다.

시작 코드 개선
--check-readiness는 ROS 초기화 없이 설정상 미검증 항목을 JSON으로 출력.
기본 실행의 servo_release_blocked는 traceback 대신 NOT_EXECUTED JSON과
종료 코드 2를 출력한다. 그 밖의 PermissionError를 로봇 명령 0회로
잘못 보고하지 않도록 이 특정 preflight 예외만 처리한다.
